# 指标与判定标准

PRD 有明确预算时以 PRD 为准；否则用下表默认值。

## 启动

| 指标 | 模拟器 debug | 真机 profile |
|---|---|---|
| `QA first screen`（main 到首屏可交互） | ≤ 2000 ms（参考） | ≤ 1000 ms（门槛） |

首屏慢的常见原因：启动时等待磁盘或 FFI 插件的首次调用（如 `path_provider`）、闪屏最短时长设得过长、启动时同步排通知队列。

## 帧耗时（按动作）

`FrameProbe.measure()` 对每个动作输出：`frames`、`build p50/p90/max`、`raster p90/max`、`over16ms`。

| 判定 | 模拟器 debug | 真机 profile |
|---|---|---|
| 超过 16ms 的帧占比 | ≤ 10%，且集中在首次进入页面 | ≤ 1%（60Hz）；ProMotion 设备参考 8.3ms |
| build p90 | ≤ 16 ms | ≤ 8 ms |
| 单帧最大值 | ≤ 100 ms（仅首帧可超） | ≤ 32 ms |
| 连续掉帧 | 不允许出现在滚动和转场中 | 不允许 |

debug 模式下帧耗时会被放大数倍，所以模拟器数据只作上限参考，不能作为 release 结论。

`run_autotest.py` 的判定方式：

- 模拟器的首屏或帧耗时超过参考值时记为 **WARN**，不阻塞总 Gate。报告的“说明”里要写原因（例如首帧构建、debug 放大），或者到真机复核。
- 真机超过门槛时记为 **FAIL**，必须修复，或者以用户签字的 deferred 阻塞项处理。

## 系统能力

| 项 | 通过标准 |
|---|---|
| 通知 | 已授权时 `pending == planned`，且 planned > 0 |
| 相册授权轮 | outcome = saved |
| 相册拒绝轮 | outcome = 拒绝降级（如 albumDenied），有提示 |
| 商店不可用 | 在超时（默认 15s）内返回，按钮恢复可点 |
| 导出渲染 | ≤ 1500 ms（模拟器 debug 参考） |

## 无障碍（L1）

| 项 | 标准 |
|---|---|
| 点按目标 | iOS ≥ 44×44pt；有标签 |
| 文字对比度 | ≥ 4.5:1（大字 ≥ 3:1） |
| 动态字体 | ×1.35 与 ×2.0 无溢出；App 可限制最大缩放（建议 ≥1.3），Tab 栏可更低 |
| VoiceOver | 主路径控件有标签、按钮语义与选中态 |

## 主路径稳定性

主路径 drive 连续 N 遍（默认 3）全部成功；任何一遍失败都要找到原因，不得只取成功的那遍。
