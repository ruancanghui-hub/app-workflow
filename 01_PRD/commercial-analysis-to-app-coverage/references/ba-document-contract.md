# 商业分析文档契约

从商业分析 Markdown 抽取下列字段。缺必填项时：智能模式可推定并记入 assumptions；深度模式先问用户补全。

## 识别文件名

- `商业分析.md` / `商业分析*.md`
- `business-analysis.md` / `business-analysis*.md`
- 用户 `@` 的任意 `.md`（内容匹配下述章节亦可）

## 必填抽取字段

| 字段 | 典型章节线索 | 写入下游 |
|---|---|---|
| 产品名 | 概述 / 定位标题 | metadata.产品名、slug |
| 一句话定位 | 产品定位段落 | intake.one_liner |
| 主用户（至少一个） | 用户画像 | metadata.目标用户（对齐后可收窄） |
| 竞品名称或链接 | 竞争格局 | intake.competitors、Phase 1 调研 |
| 差异化 / 护城河 | 壁垒、特色 | 决策树 + 功能分期 |
| 变现模式 | Freemium / 订阅 / 买断 | metadata.商业策略 |
| 功能与优先级 | 功能表、P0/P1 | 蓝图与 MVP In/Out |
| 合规约束 | 商店分类、免责、禁用词 | PRD 隐私与发布门 |

## 可选字段

| 字段 | 用途 |
|---|---|
| 次要 / 垂直用户 | 标为非 MVP 或 P2 延伸 |
| 硬件 / 穿戴方案 | 矛盾门：自有硬件 vs 系统健康 API |
| 平台暗示 | iOS / Android / 双端 |
| 内嵌 PRD 草稿 | **仅作输入**，必须重写并校验五文件 |
| 技术机制笔记 | 供 Phase 1 sources，不作实现承诺 |

## 章节映射（Refocus 样例）

| 样例标题 | 契约字段 |
|---|---|
| 项目概述 / Executive Summary | 定位、背景 |
| 目标用户画像 | 主/次用户 |
| 市场竞争与差异化 | 竞品、护城河 |
| 商业化与变现 | 商业策略 |
| 功能架构 / 功能需求表 | 功能与优先级 |
| 平台合规与审核 | 合规约束 |

## 抽取完成标准

- 产品名、定位、至少一名用户、至少一名竞品、变现、至少一条带优先级的功能、合规意图（或明确「无特殊合规」推定）均有值或已标「缺失→推定」。
- 内嵌「PRD」章节不视为 `docs/product/` 交付物。
