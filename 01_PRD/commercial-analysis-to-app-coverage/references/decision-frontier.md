# 决策前沿（商业分析 → MVP）

从商业分析进入 APP 覆盖时，按轮次对齐。每轮只问**前置已决**的问题；每题给推荐答案。未共识不得写 Phase 1 成稿。

## Round 模板

```
❓ **Qn** - **标题**: 题干与选项

➡️ 推荐答案
```

## 强制矛盾（任一即开闸）

1. **护城河 vs 优先级：** 文案称核心差异，功能表为 P1/P2/R&D  
2. **画像过多：** 多个「核心」用户无单一 MVP 验证对象  
3. **硬件过早：** 自有手环/NFC 捆绑进 P0，无供应链验证  
4. **医疗越界：** 诊断/治疗措辞与 Health & Fitness 定位冲突  

## 推荐默认（智能模式可作三问核心）

| 决策 | 推荐 | 说明 |
|---|---|---|
| 主用户 | 商业分析「核心群体」中最可对标竞品的一类 | 其余进 assumptions「后续」 |
| MVP 闭环 | 软件主路径可独立成立 | 差异化能力进 P1+ |
| 穿戴 | 系统健康数据（如 HealthKit），非自研硬件 | 自有硬件 → R&D |
| 平台 | 依用户；双端则「工程双端、先发一平台」 | 避免同日功能对齐硬承诺 |
| 假 P0 | 与主闭环无关的提醒/扩展砍出 MVP | 记入 Out of Scope |
| 变现 | 保留 BA 的 Freemium/订阅若已写明 | 细节可推定并记录 |
| 语种 | 问用户或推定；设置内切换则记 P0 | — |

## 智能模式：最多三题

优先问会改变范围的三项（示例）：

1. 平台与上架节奏  
2. MVP 主用户（若 BA 列出多个）  
3. 护城河进 MVP 还是 P1（及穿戴策略）  

其余用上表推荐默认并写入 assumptions。

## 深度模式：多轮前沿

**Round 1（根决策）：** 模式已定前提下 → 平台、主用户、穿戴策略、MVP 是否含护城河。  
**Round 2（展开）：** 双端节奏、从 BA 功能表砍掉的 P0、Android/iOS 能力不对齐、变现上架日起否启用。  
**Round 3（边界）：** 干预形态、拦截范围（仅 App vs 网站）、再次干预、语种。  
**收尾：** 展示共识清单 → 用户确认「可以开跑 Phase 1」。
